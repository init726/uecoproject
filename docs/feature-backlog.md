# 명세서 대비 추가 개발 목록

작성일: 2026-10-24. 기준: 제공된 2026-10-22 요구명세서와 현재 로컬 코드.
구현 상태는 코드 기준이며, 운영 Supabase 설정·배포 상태·실제 기기 동작은 별도 검증이 필요하다.

## 2. 먼저 마무리할 기능

- [ ] **교사 제출 이력 조회 완성 (ASG-07)**: 학생 카드에서 이전 버전 목록을 펼치고 버전별 시각·지각·파일/본문을 확인한다. 다른 클래스 교사와 관리자는 접근할 수 없어야 한다.
- [x] **클래스 정보 수정**: 과목명·학기·강의실·요일·교시 수정 화면과 액션 구현. 담당 교사 권한 확인, 학기별 충돌 확인, 트랜잭션 저장 적용. 운영 DB에는 `20261024_semester_timetable.sql` 적용 필요.
- [ ] **관리자 클래스 관리 범위 맞추기**: 명세 권한표는 전체 클래스 생성·수정을 허용하지만 현재 RLS는 담당 교사 중심이다. 전체 조회·교사 지정 생성·수정 기능을 구현할지, 명세를 축소할지 결정한다. 제출물 접근 금지는 유지한다.
- [ ] **마감 임박 표시 보완 (TT-03)**: 예를 들어 24시간 이내 과제를 별도 표시하고 마감 지난 과제와 구분한다. 24시간은 제안 기준으로 확정이 필요하다.
- [ ] **임시저장 계정 분리 (ASG-03 보완)**: 현재 localStorage 키가 과제 ID만 포함해 같은 브라우저에서 다른 학생이 로그인하면 초안이 섞일 수 있다. 사용자 ID를 키에 포함하고 로그아웃 후 초안 처리 정책을 정한다. 현재 임시저장은 기기 간 동기화되지 않는다.

## 3. 새 기능 개발 순서

### 1순위: AI 생기부 글 피드백 (ASG-08, SEC-07)

- [ ] 제출 전 글 작성 화면에 피드백 요청 버튼을 제공한다.
- [ ] 구체성, 활동 근거, 배운 점, 문장 명확성 중심으로 개선 의견을 표시한다.
- [ ] 완성 글 대필 대신 질문·수정 방향을 제시한다.
- [ ] 이름·학번 등 개인정보를 외부 전송 전에 가리고 불필요한 프로필은 보내지 않는다.
- [ ] API 호출은 서버에서 처리하고, 참여 학생 권한과 입력 길이를 검증한다.
- [ ] 호출 횟수·중복 요청·시간 초과·비용 한도를 관리한다. AI 실패 중에도 일반 제출은 가능해야 한다.

### 2순위: 교사 피드백 (ASG-06)

- [ ] 교사가 특정 제출 버전에 피드백을 남긴다.
- [ ] 학생이 자기 제출물 피드백을 확인한다.
- [ ] 피드백 작성·수정 시각과 대상 버전을 표시한다.
- [ ] 학생 본인·담당 교사만 읽는 RLS를 추가한다.

### 3순위: 계정 복구·로그인 보호 (AUTH-04, SEC-08)

- [ ] 현재 있는 관리자 초기화 외에 사용자가 복구를 요청할 수 있는 흐름을 마련한다.
- [ ] 이메일 재설정을 구현하려면 실제 이메일 수집·검증이 먼저 필요하다. 현재 `아이디@id.invalid` 주소로는 복구 메일을 받을 수 없다.
- [ ] 명세의 연속 로그인 5회 실패 후 일시 차단을 구현·검증한다. 공개 교사 가입에도 요청 제한을 적용한다.
- [ ] UI 카운터에 의존하지 않고 서버/인증 서비스에서 제한한다. 차단 시간과 해제 방법은 확정해야 한다.

### 4순위: 설문 (SRV-01~03)

- [ ] 교사: 질문 편집, 단일 선택·복수 선택·주관식 질문, 설문 게시.
- [ ] 학생: 참여 클래스 설문 조회·응답.
- [ ] 결과: 객관식 막대그래프, 주관식 목록. 담당 교사와 관리자 조회 권한.
- [ ] 설문별 익명 여부 설정. 익명 응답에서 교사가 개인을 식별할 수 있는 값이나 연결을 제공하지 않는다.
- [ ] 익명성과 중복 응답 방지를 함께 설계한다. 단순히 student_id를 제거하는 것만으로 두 요구가 모두 해결되지는 않는다.
- [ ] 응답 마감, 재응답 허용, 최소 응답 수에 따른 결과 공개 기준은 추가 정책으로 결정한다.

### 5순위: AI 설문 요약 (SRV-04, SEC-07)

- [ ] 주관식 답변을 주제별로 묶고 주요 의견을 요약한다.
- [ ] 전송 전 개인정보를 가리고 담당 교사·관리자 권한을 검증한다.
- [ ] 원문과 AI 요약을 구분하며, 응답 변경 시 요약 갱신 방법을 정한다.

### 6순위: 커뮤니티와 신고 관리 (COM-01~04)

- [ ] 학교 전체 게시판: 목록·상세·작성, 댓글, 좋아요, 본인 글 삭제.
- [ ] 익명 표시: 일반 조회 응답에 작성자 식별정보가 노출되지 않게 한다. 서버에는 신고 처리용 작성자를 기록한다.
- [ ] 신고 사유 입력, 동일 사용자 중복 신고 방지, 서로 다른 사용자 신고 3회 시 자동 숨김.
- [ ] 관리자 신고 목록·내용 검토·복구·삭제.
- [ ] 욕설·비하 표현에 대한 게시 전 경고. 경고 기준과 오탐 대응 방식 결정.
- [ ] 숨겨진 글이 직접 URL이나 API 조회로 노출되지 않도록 RLS/조회 정책 적용.

### 이후: 화면 안 알림

- [ ] 새 공지·과제·교사 피드백 배지와 읽음 상태.
- [ ] 마감 임박 표시. 웹 푸시는 선택 사항이며 명세의 필수 구현은 아니다.

## 4. 기능 추가 전후에 함께 고칠 안정성 항목

- [ ] 임시 비밀번호 변경 필수 상태를 페이지뿐 아니라 서버 액션·직접 DB/Storage 접근에도 일관되게 적용한다.
- [x] 클래스 생성·수정과 시간표 저장을 `save_class` DB 트랜잭션으로 묶어 부분 생성 방지.
- [ ] 파일 업로드 성공 후 제출 실패 시 남은 파일 정리. 마감 후 업로드만 반복되는 경우도 고려.
- [ ] 계정 삭제 시 Storage 삭제 실패를 확인하고 복구·재시도할 수 있게 한다. 제출 기록 없는 업로드 파일도 정리 대상으로 고려.
- [ ] 제출 버전 `max(version)+1` 동시성 충돌 방지.
- [ ] 조회 실패와 빈 목록을 구분하고, 초대코드 재발급·학생 내보내기·승인 등의 실패를 사용자에게 표시.
- [ ] 비밀번호 변경 필수 플래그 해제와 세션 갱신 오류 처리.
- [ ] 실제 Supabase 공개 회원가입 설정 점검. 학생은 관리자 발급만 가능하다는 정책을 직접 Auth API로 우회할 수 없는지 검증.

## 5. 명세와 현재 제품 정책을 맞출 항목

| 항목 | 명세 | 현재 | 필요한 결정 |
| --- | --- | --- | --- |
| 가입·로그인 | 이메일 가입·역할 선택 | 아이디 로그인, 학생 관리자 발급 | 현재 정책 유지 시 AUTH-01·화면 명세 갱신 |
| 비밀번호 복구 | 이메일 재설정 | 관리자 초기화 | 실제 이메일 도입 또는 관리자 복구 절차로 명세 변경 |
| 관리자 클래스 권한 | 전체 생성·수정 | 담당 교사 중심 | 구현 확장 또는 권한표 수정 |
| 개인정보 | 이름·학번·이메일 | 아이디·교과, 발급 시 선택적 전화번호 처리 | 실제 수집·이용·보관 안내와 학생 동의 절차 정합성 확보 |

관리자 발급 시 코드는 `privacy_agreed: true`를 넣는다. 이것만으로 학생 본인의 안내 확인이나 동의 절차가 구현됐다고 보기는 어렵다.

## 6. 완료 여부를 검증할 작업

- [ ] 375px 화면에서 학생·교사·관리자 주요 화면의 가로 넘침 점검.
- [ ] 로그인 후 홈 → 클래스 → 과제 → 제출 흐름의 클릭 수와 사용성 점검.
- [ ] 실제 Supabase에서 학생 A/B·담당/타 교사·관리자 간 DB/파일 권한 검증.
- [ ] 브라우저 종료 후 세션 유지, 임시 비밀번호, 승인 대기, 계정 전환 시나리오 점검.
- [ ] 마감 직전 동시 제출·재제출 및 600명/교사 50명 목표의 부하·조회량·저장 용량 점검.
- [ ] 배포 빌드·배포 URL·환경변수·데모 데이터·발표 PDF 준비 여부 확인.

앞선 로컬 분석에서 lint, TypeScript 검사, PGlite DB 보안 테스트 46개는 통과했다. 이는 운영 서비스 전체 검증을 대신하지 않는다.

## 추천 실행 순서

1. 이력 조회·클래스 수정·초안 계정 분리와 기존 실패 처리 보완.
2. AI 글 피드백 1개를 끝까지 완성.
3. 교사 피드백과 계정 복구·로그인 보호.
4. 설문 기본 기능 → AI 설문 요약.
5. 커뮤니티와 신고 운영 기능.

실시간 채팅, 네이티브 앱, NEIS 연동은 원래 명세의 제외 범위로 유지한다.

## 2026-10-24 시간표·화면 개편

- 공통 학기 목록, 홈 학기 필터, 다른 학기 간 충돌 제외.

- 가상 데이터로 375px/1280px 화면 확인. 운영 Supabase 적용·실계정 연동 확인은 별도.

## 2026-10-25 추가 구현

이 문서의 이전 체크리스트보다 최신 코드 상태를 우선한다. 제출 취소, 교사 버전별 이력·피드백, 초안 계정 분리, 과제 몰림 조회, Ollama 글 피드백·자기평가서 초안·설문 요약, 설문, 알림, 관리자 확인 방식 계정 복구, 앱 서버의 로그인·가입·복구 요청 제한을 구현했다. 운영 DB 업데이트 및 로컬 모델 설정은 [추가 기능 안내](school-workflows.md)를 따른다. 커뮤니티와 신고 운영, Supabase Auth 직접 요청 제한 설정, 예약 마감 푸시는 남아 있다.
