# 수업 운영 추가 기능

## 기존 프로젝트에 적용

1. Supabase SQL Editor에서 `supabase/update-school-workflows.sql` 전체를 한 번 실행한다. 기존 시간표·엑셀 등록 마이그레이션이 적용된 프로젝트용이다. 반복 실행해도 제출 기록과 응답을 보존한다. 새 프로젝트는 `supabase/schema.sql`만 실행한다.
2. `.env.local`에 아래 설정을 추가한다. 모델명은 `ollama list`에 나오는 로컬 모델명이다. 현재 개발 기기에 설치된 모델은 `qwen3:4b`이다.

```env
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:4b
OLLAMA_TIMEOUT_MS=120000
```

3. `npm run ai:serve`로 Ollama를 실행하고, 별도 터미널에서 `npm run dev`를 실행한다. Ollama가 이미 실행 중이면 다시 실행할 필요가 없다. AI 실행 스크립트는 루프백 주소만 사용하고 Ollama 클라우드 기능을 비활성화한다. 외부 API 키는 필요하지 않다.

`localhost`는 웹서버가 실행되는 기기를 뜻한다. 배포할 때는 Next.js 서버에서 접근할 수 있는 학교 내부 Ollama 서버 주소를 지정해야 한다. 학생의 브라우저가 Ollama에 직접 접속하지 않는다. 모델 다운로드·교체는 자동으로 하지 않는다.

## 기능과 사용 위치

- 과제 상세: 학생 제출 취소, 모든 제출 버전 보존, 교사의 이전 버전 열람과 버전별 피드백. 마감 이후에는 제출 취소 불가.
- 과제 만들기: 마감일 선택 후 과제 몰림 조회. 같은 학생들이 듣는 다른 수업의 날짜별 과제 수를 집계한다. 다른 학생의 제출물 내용은 반환하지 않는다.
- 글 과제: 현재 글에 대한 AI 피드백. 교사가 자기평가서로 지정한 글 과제에서는 같은 수업에 내가 제출한 글로 검토용 초안 생성. 취소된 최신 제출과 파일 제출은 자료에서 제외한다. 교사에게는 AI 초안 요청 횟수를 표시한다. 실패한 요청도 집계한다.
- 클래스 설문: 교사가 단일 선택·복수 선택·주관식 질문을 게시한다. 게시 후 질문·익명 설정은 변경하지 않는다. 학생은 마감 전 응답을 수정할 수 있고, 교사는 조기 마감할 수 있다.
- 설문 결과: 담당 교사 및 관리자 열람. 익명 설문은 마감 후 3명 이상일 때 공개하며 응답자 식별자·시각을 제공하지 않는다. 계정 연결은 중복 응답 방지를 위해 서버에 보관한다. 기명 설문에는 이름·학번이 표시된다. 담당 교사는 공개 가능한 주관식 응답을 AI로 요약할 수 있다. 관리자는 관리자 메뉴의 설문 결과에서 조회한다.
- 학교 알림 (`/school-notifications`, `learning_notifications`): 새 과제·공지·설문 및 피드백 도착 시 생성한다. 학생 상단과 교사 메뉴에서 최근 100개를 확인하고 모두 읽음 처리한다. 기존 게시물에 대한 알림을 소급 생성하지 않는다. 마감 임박 표시는 홈과 할 일 화면을 사용하며 예약 푸시 기능은 포함하지 않는다.
- 계정 복구: 로그인 화면 → 복구 요청 → 관리자 계정 복구 요청. 학교 담당자가 본인을 확인한 뒤 기존 사용자 관리에서 초기화하고 안전하게 전달한 후 처리 완료한다. 요청 접수만으로 자동 초기화하지 않는다.

## AI 처리와 한도

- Ollama `/api/chat`을 서버에서 호출하며 최종 답변만 표시한다. 생각 과정은 표시하지 않는다. 모델은 환경변수로만 선택하고 클라이언트가 서버 주소나 모델을 지정할 수 없다. `:cloud` 모델과 Ollama 클라우드 주소는 허용하지 않는다.
- 현재 글이나 기존 제출 글에서 알려진 이름·학번·이메일·전화번호 등을 가린다. 자유 서술의 모든 개인정보를 자동으로 찾는 것은 아니므로 처리 안내를 제공하고 사용자가 확인하도록 한다.
- 사용자가 확인을 선택한 뒤 요청한다. 모델을 설정하지 않았거나 서버가 꺼져 있어도 일반 작성·제출은 동작한다.
- AI는 학교 전체 24시간 200회, 사용자 10회, 과제·설문별 3회, 연속 요청 간격 30초를 적용한다. DB 트랜잭션 안에서 한도를 확보한다. 실패한 요청도 한도에 포함된다.
- 입력은 최대 16,000자, 출력은 2,000토큰, 기본 제한 시간 120초다. 설문 요약은 긴 원문이 잘릴 수 있음을 화면에 안내한다. 초안은 사실 검토 후 학생이 직접 수정해야 한다.
- 학생의 능력·성적을 자동 평가하거나 AI가 최종 제출을 대신하지 않는다.
- API 규격: https://docs.ollama.com/api/chat / https://docs.ollama.com/capabilities/thinking

## 로그인 보호

로그인 시도 횟수는 앱에서 제한하지 않는다(Supabase Auth 자체의 기본 요청 제한만 적용). 교사 가입·계정 복구 요청에는 DB 기반 제한을 적용한다. 계정 식별자는 해시로 저장한다. 제한 테이블은 클라이언트가 직접 조작할 수 없다.

이 제한은 앱 서버 액션에 적용된다. Supabase Auth 직접 요청까지 보호하려면 운영 Supabase의 인증 Rate Limits와 CAPTCHA 설정도 별도로 구성해야 한다. 공개 교사 가입에도 같은 운영 설정을 적용한다. 신뢰할 수 있는 프록시가 IP 헤더를 덮어쓰는 배포에서만 `TRUST_PROXY_IP=true`를 설정하면 IP 제한이 추가된다. 잘못 설정된 프록시 헤더를 신뢰하지 않도록 기본값은 false다.

새 기능의 실제 운영 데이터 흐름은 운영 DB 업데이트 후 학생·교사·관리자 계정으로 확인한다. 커뮤니티는 협업자가 개발하는 범위로 남겨 두었다.

협업 중인 커뮤니티의 기존 `notifications` 테이블·알림 정책·경로는 변경하지 않는다. 수업 운영 알림은 별도 테이블과 경로를 사용한다.

## DB 업데이트 전 호환 동작

제출 취소 열이나 과제 purpose 열이 아직 없으면 기존 컬럼으로 다시 조회하여 학생·교사 홈, 클래스, 과제 상세와 일반 제출을 유지한다. 누락된 설문·피드백은 기존 화면을 막지 않으며, 지원되지 않는 취소·피드백 버튼은 표시하지 않는다. 네트워크·권한 오류는 빈 목록으로 처리하지 않는다. 일반 과제 생성은 새 purpose 열 없이도 가능하며 자기평가서 지정에는 DB 업데이트가 필요하다.

개발 모드에서만 DB 요청 제한 함수가 없으면 같은 프로세스의 임시 제한기로 가입·복구 요청 횟수를 제한한다. 운영 모드는 이 대체 동작을 사용하지 않으므로 배포 전 DB 업데이트가 필수다.

## 한 학교의 표시 이름

신정고등학교 한 곳만 운영하는 서비스다. 학교 이름(신정고등학교)과 서비스 이름(Cue)은 설정 없이 `src/lib/constants.ts`의 `SCHOOL_NAME`, `SERVICE_NAME`에 고정되어 있다.
